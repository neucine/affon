# CUDA f32 scatter-add review, 2026-11-07

The reviewed 11,946-cell CUDA sweep identified f32 scatter-add as the next largest absolute gap after top-k and reduce-to-shape. Its largest cell was a strided rank-two scatter with about 2.96 ms of operator time beyond the PyTorch peer. The old rank-two CUDA kernel copied and applied every update in one GPU thread.

The final replacement routes **all rank-two f32 inputs** through the existing parallel, output-centric CUDA kernel. Each output scans updates in their original order, preserving deterministic f32 addition order and duplicate-index behavior. Dispatch uses runtime rank; it contains no catalog IDs, fixed dimensions, or input-value tests. The first candidate failed 32 offset-view numerical cells because the parallel kernel subtracted the view offset from its scan base. That incomplete run is retained in `rejected-first-candidate/`. The passing intermediate version kept offset views on the serial path; its reports and [review](intermediate-summary.json) are retained. The final version fixes the parallel kernel's index and update scan addresses, so offset views use the parallel path too.

The [baseline](baseline/report.md) and [final candidate](final-candidate/report.md) used the same frozen [197-cell catalog](catalog.json), RTX 3090, Zig 0.17.0 build, PyTorch 2.11.0+cu128 peer, and 10 iterations × 5 samples × 3 rounds. Each batch passed all 197 numerical probes, operator peers, and Program peers. The [binary-bound baseline audit](baseline-audit.json) and [final audit](final-candidate-audit.json) verify the catalog, binary, raw rounds, paths, and complete reports. PyTorch masks invalid indices before its scatter operation to match Affon's skip-update contract; peer timing includes that mask.

Among the 132 changed rank-two cells, including 32 offset views, all 132 improved in both execution-phase medians. Median speedup was **10.46× operator** and **8.29× Program**. The largest baseline cell, `strided/cols_axis0_r33_c129`, changed from **2.9506 to 0.0233 ms** operator execution and **2.9553 to 0.0289 ms** Program execution. These are controlled diagnostic measurements on this GPU, not a universal speedup claim.

The [final versus original regression report](regression-final-vs-original/regression.md) found zero changed contracts, correctness regressions, or timing suspects. The [final versus intermediate comparison](regression-final-vs-intermediate/regression.md) flagged one relative timing suspect in an unchanged cell; Affon's execution time was within 1% and only PyTorch peer time shifted. The intermediate run's separate unchanged rank-three timing spike and its [focused repeat](suspect-repeat/report.md) remain documented in the [intermediate regression](regression/regression.md). The original reports are preserved in [the first archive](archive-before-promotion/), and the intermediate entries in [the final promotion archive](archive-intermediate-before-final/).
