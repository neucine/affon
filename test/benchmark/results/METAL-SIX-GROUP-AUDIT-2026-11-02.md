# Metal six-group optimization audit

The [optimization direction audit](METAL-OPTIMIZATION-DIRECTION-AUDIT-2026-11-02.md) parks further gap chasing and assesses whether these cell-level results support representative workload performance.

The counts below are historical measurements from before the 2026-11-03 Metal GPU-default policy correction. The shared-buffer CPU paths now require explicit opt-in; rerun affected catalogs before interpreting the aggregate gaps as current performance.

The shared-buffer CPU paths in this audit improve isolated, host-visible calls under explicit dispatch guards. Their candidate-gap reductions are diagnostic measurements, not evidence that GPU-resident or chained workloads became faster. The guards reject pending commands, active timing or tracing, and private buffers, so those workloads use the GPU paths. Treat the shared-buffer reductions as provisional capability claims until representative end-to-end workloads show a speedup across sizes and producer-consumer chains. GPU kernel and addressing changes require separate evaluation.

Scope of this audit: parity cell counts describe validation, not the number of performance gaps eliminated. The current operator summary reports 2,128 Metal `candidate_gap` cells, down from 3,031 before the gather promotion. The gather, scatter, f32 layer_norm, BF16 matmul, subsequent f32 matmul, one_hot, and quantized_matmul promotions eliminated 156, 103, 66, 87, 61, 231, and 170 aggregate gaps respectively. Five additional cross_entropy_indexed gaps disappeared when the mixed-operation indexed catalog was refreshed; they are not attributed to the matmul implementation. The six groups account for 338 remaining gaps: matmul 126, layer_norm 111, scatter_add 100, gather 1, dot 0, and where 0. Promoted report counts do not imply equal gap reductions.

Target: Mac16,1 / macOS 26.6.2 / arm64. The current Affon build is `zig build -Doptimize=ReleaseFast`, with PyTorch from `apps/hf-inference/artifacts/preparation-env/bin/python` for parity. Each listed manifest was inspected for `correct` numerical status and `passed` operator and Program status on every cell.
