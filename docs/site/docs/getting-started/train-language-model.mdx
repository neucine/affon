title: Train a small language model in TypeScript
description: Run Affon's WikiText-2 decoder example, inspect its Program, and check training loss and checkpoints.
---

Can a TypeScript program train a language model, rather than only call one? This
example trains a small decoder on the bundled WikiText-2 data. It covers text
preparation, a model with attention, a training step, validation, and a saved
checkpoint. The run below shows the model learning over 256 training batches;
it does not train a useful text generator.

## Train with a smaller tokenizer

This workflow uses **Affon 0.4.2 on macOS arm64 using Metal**. Install
[Affon](/docs/getting-started/installation/), open a new terminal if the
installer updated your `PATH`, and check `affon --version`. Then run from a
fresh source checkout:

```sh
git clone https://github.com/neucine/affon.git
cd affon
mkdir -p apps/decoder-lm/artifacts/wikitext-8k
RUNTIME_PACKAGE_PATH="$PWD/packages" \
  AFFON_TRAIN_CONFIG=apps/decoder-lm/configs/train-decoder-lm-wikitext-8k.config.json \
  affon run apps/decoder-lm/train.ts
```

The configuration uses a tokenizer trained on the WikiText-2 training split
with **8,192 tokens**, a six-layer decoder, and 256-token windows. It caps
training at 256 batches and evaluates up to 32 validation batches. It writes
token caches, a summary, and a checkpoint under
`apps/decoder-lm/artifacts/wikitext-8k/` in the checkout. Training takes
longer than a quick installation check.

In the saved Metal run, validation loss fell from **9.070 to 6.579** after
256 steps, final training loss was **7.093**, and the app saved
`first-run-epoch-1`. Your exact numbers may vary. The generated sample still
repeated words and symbols. This is a capped run within one epoch; the result
shows learning on these batches, not useful text generation. Loss values from
different tokenizers cannot be compared directly.

## Two full epochs on CUDA

A longer run used the same 8,192-token vocabulary, six decoder layers, and
256-token windows on an RTX 3090. Each epoch covered 4,995 batches of four
windows, followed by the full validation split.

| Completed epoch | Training loss | Validation loss | Validation perplexity |
| --- | ---: | ---: | ---: |
| 1 | 6.1247 | 5.4641 | 236.1 |
| 2 | 5.2572 | 5.1339 | 169.7 |

Perplexity expresses next-token prediction error; lower is better for the
same tokenizer and evaluation data. Training loss is the average while the
weights change during each epoch. Validation uses the saved end-of-epoch
weights on held-out text.

The model is learning, but its text is still repetitive and incoherent.
With the same prompt, `The history of`, epoch two began:

> The history of the U.S.S.S.D.S.S.S. were would , was the of the B.S.S..

Epoch one used the published Affon 0.4.2 binary. Epoch two restored its model
and Adam optimizer checkpoint using a local runtime with a CUDA reduction
fix. The first resumed loss agreed within 0.000001. That fix is not part of
the published 0.4.2 binary. These are interim results from a continuing run,
not a text-quality benchmark or a speed comparison with other frameworks.

## Where Affon fits

The [model source](https://github.com/neucine/affon/blob/main/apps/decoder-lm/src/model.ts)
defines embeddings, causal attention, decoder blocks, and an output head. The
[workflow](https://github.com/neucine/affon/blob/main/apps/decoder-lm/src/workflow.ts)
prepares text batches, creates a `Session`, runs training and validation, and
saves the checkpoint.

Affon calls the model's computational definition a **Program**. It names the
inputs, parameters, operations, and nested decoder components. The workflow
derives a training Program from the model, a cross-entropy loss, and an
optimizer, then compiles it for the selected device. You can inspect the
Program before running it to see its tensor shapes and where each parameter
belongs. See the [decoder app guide](https://github.com/neucine/affon/tree/main/apps/decoder-lm)
for the code and the [compute concepts](/docs/core/compute/) for Program and
Session.

## Continue training

The [main WikiText configuration](https://github.com/neucine/affon/blob/main/apps/decoder-lm/configs/train-decoder-lm-wikitext.config.json)
sets a longer run with the GPT-2 tokenizer. Its loss values use a different
token vocabulary. Read its batch, epoch, checkpoint, and device settings
before using it. To recreate the smaller tokenizer, install Python
`tokenizers==0.22.2` and run
`python3 apps/decoder-lm/train-wikitext-tokenizer.py` from the repository root.
For a smaller introduction to Programs, try the
[first Program](/docs/getting-started/first-program/).
