title: Train a small language model in TypeScript
description: Run Affon's WikiText-2 decoder example, inspect its Program, and check training loss and checkpoints.
---

Can a TypeScript program train a language model, rather than only call one? This
example trains a small decoder on the bundled WikiText-2 data. It covers text
preparation, a model with attention, a training step, validation, and a saved
checkpoint. The short run below checks that the path works; it does not train a
useful text generator.

## Run the short training check

This run was checked with **Affon 0.4.2 on macOS arm64 using Metal**. Install
[Affon](/docs/getting-started/installation/), open a new terminal if the
installer updated your `PATH`, and check `affon --version`. Then run from a
fresh source checkout:

```sh
git clone https://github.com/neucine/affon.git
cd affon
RUNTIME_PACKAGE_PATH="$PWD/packages" \
  AFFON_TRAIN_CONFIG=apps/decoder-lm/configs/train-decoder-lm-wikitext-debug.config.json \
  affon run apps/decoder-lm/train.ts
```

The configuration uses a six-layer decoder, 256-token windows, 32 training
batches, and eight validation batches. It writes token caches, a summary, and a
checkpoint under `apps/decoder-lm/artifacts/wikitext/` in the checkout. It also
generates a short text sample; do not judge model quality from this small run.

In the verified run, validation loss fell from **10.832 to 9.833** after 32
steps, and the app saved `clean-debug-run-epoch-1`. Your exact numbers may
vary. The final lines should include `training complete`, `steps: 32`,
`initialValLoss`, `finalValLoss`, and a checkpoint path. A falling loss here
shows that this bounded training path executed; it is not a quality or speed
comparison with other runtimes.

## Where Affon fits

The [model source](https://github.com/neucine/affon/blob/main/apps/decoder-lm/src/model.ts)
defines embeddings, causal attention, decoder blocks, and an output head. The
[workflow](https://github.com/neucine/affon/blob/main/apps/decoder-lm/src/workflow.ts)
prepares text batches, creates a `Session`, runs training and validation, and
saves the checkpoint.

Affon calls the model's computational definition a **Program**. It names the
inputs, parameters, operations, and nested decoder components. The workflow
derives a training Program from the model, a cross-entropy loss, and an
optimizer, then compiles it for the selected device. You can inspect the
Program before running it to see its tensor shapes and where each parameter
belongs. See the [decoder app guide](https://github.com/neucine/affon/tree/main/apps/decoder-lm)
for the code and the [compute concepts](/docs/core/compute/) for Program and
Session.
